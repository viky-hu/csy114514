# 组件错题本

## 模块地图

- `app/login-window-demo.tsx`：顶层窗口流转，只维护路由级状态。
- `app/windows/login/`：登录引导、登录表单、注册切换。
- `app/windows/product/`：三板块产品介绍与全屏滚动。
- `app/windows/main/`：交互对话、模型配置、溯源、知识图谱。
- `app/windows/database/`：聚类列表、聚类详情、文件管理。
- `app/windows/macro/`：D1 到 D5 宏观可视化。
- `app/windows/shared/`：跨窗口共享导航、坐标、动画工具。

## 常见错题

### 错题 1：窗口之间互相改内部状态

错误做法：产品介绍窗口直接修改交互对话窗口的内部状态。

正确做法：通过顶层回调或明确 props 契约切换窗口，内部状态由对应窗口自己管理。

### 错题 2：复制粘贴共享逻辑

错误做法：多个窗口分别写一套坐标换算、GSAP 插件注册、导航按钮样式。

正确做法：坐标和动画工具放入 `shared/coords.ts`、`shared/animation.ts`，共享 UI 放入 `shared`，业务私有逻辑留在窗口内。

### 错题 3：纯渲染组件偷偷管理状态

错误做法：`ChatHistoryGroup.tsx` 自己 fetch、自己管理动画、自己持有状态。

正确做法：纯渲染组件只接收 props 和回调；状态、API、GSAP 编排在主责组件或服务层。

### 错题 4：把复杂后端聚合塞进 UI 文件

错误做法：在组件内同时处理鉴权、超时、节点失败、响应归一化。

正确做法：组件只消费稳定业务结构；后端通信经服务层和 BFF 处理。

## 新组件落地步骤

1. 先声明主责文件和协同文件。
2. 判断是否跨窗口复用，能复用则进 `shared`，否则留在窗口目录。
3. 声明状态唯一来源，避免状态双源。
4. 检查是否出现两个以上重复分支，出现则当次收敛。
5. 若职责变化，更新架构文档。

## 验收标准

- 新增组件职责单一。
- 交互叶子节点可点击，全屏层不抢事件。
- 共享逻辑没有窗口私有状态污染。
- 后续新增窗口或模式时不需要散改多处硬编码。
