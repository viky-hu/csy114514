# UI 错题本

## 项目视觉基线

- 登录窗口以白底、品牌蓝线框、蓝色文案、蓝色 Logo 为第一阶段基线，进入登录态后变为蓝色表单区域。
- 产品介绍窗口要求一屏一个 panel，黑色动态主视觉、蓝色主介绍、蓝色延展各有独立层级。
- 交互对话窗口由点阵背景、SVG 画布、聊天面板、侧滑菜单组成，层级和点击域必须稳定。
- 字体重点使用 DingTalk JinBuTi，尤其 Panel 2 shuffle 文案和交互提示语。
- 项目默认需要考虑 Edge + 125% 缩放验收。

## 常见错题

### 错题 1：全屏容器抢点击

错误做法：`.chat-interaction-layer` 或菜单全屏层设置 `pointer-events: auto`。

正确做法：全屏占位层默认 `pointer-events: none`，只有按钮、输入框、消息区等叶子节点设置 `auto`。

### 错题 2：SVG 层盖住 WebGL 背景

错误做法：Panel 2 的 SVG 线条层添加全屏不透明 `rect`。

正确做法：Panel 2 层级固定为流光背景、SVG 线条、文案；SVG 只画线条，不画遮挡底板。

### 错题 3：背景变成信息层

错误做法：Three.js Beams 在登录第二阶段仍高强度显示，干扰表单阅读。

正确做法：第一阶段低透明氛围，第二阶段开始后快速淡出，蓝色登录区不透明覆盖。

### 错题 4：重复百分比导致二次收缩

错误做法：外层和内层同时设置 `left: 25%; right: 25%`，导致信息流比画布更窄。

正确做法：信息流定位以全屏父容器为基准，只在一个层级使用画布坐标变量。

### 错题 5：用装饰牺牲可读性

错误做法：大面积 blur、filter、阴影、亮色边框叠加在信息文字上。

正确做法：文字、表单和气泡永远高于氛围层；必要时降低背景饱和度、速度和透明度。

## UI 验收

- 单屏界面不叠屏、不露边、不抢点击。
- 文字不被背景或线条压住。
- 交互区域在菜单开合时仍可预测。
- 125% 缩放下布局和点击域仍成立。
