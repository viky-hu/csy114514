# 仓库级交付治理

## 默认主线

第二阶段默认目标是“多节点协同检索 + 中心聚合回答”。所有联调改动优先围绕可扩展、可维护、可审计推进。

## 强制交付三件事

1. 功能归属声明：写清主责文件和协同文件。
2. 扩展性审查：不只看是否报错，还要评估后续扩展成本和边界稳定性。
3. 必要重构：发现重复逻辑、边界污染、硬编码扩散，当次收敛，不留“以后再说”。

## 文档同步门禁

当改动影响模块职责时，同步更新：

- `docs/architecture/modules-index.md`
- `docs/architecture/extension-review-checklist.md`

## 动效全局底线

- 首屏关键动画阶段不并发初始化大图谱、复杂物理布局等重模块。
- 动画属性优先 `transform` 和 `opacity`。
- hover 或频繁交互中不全量重建时间轴。
- SVG 动画优先纯描边和透明度，少用滤镜。
- 性能验收至少覆盖 Edge + 125% 缩放，并记录结论和残余风险。

## 交付说明模板

- 功能归属：主责文件；协同文件。
- 扩展性审查：新增窗口、节点、模型、字段时的扩展成本。
- 必要重构：本次收敛了什么重复、硬编码或边界污染。
- 验证：运行了什么检查，未运行则说明原因。
- 风险：仍然存在的限制和后续动作。
