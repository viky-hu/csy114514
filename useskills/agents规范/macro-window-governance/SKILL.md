# Window 2 宏观可视化治理

## 模块职责

- `MacroWindow.tsx`：宏观窗口总编排与模块联动。
- `D1Timeline.tsx`：动态更新和时间线。
- `D2Visualization.tsx`：节点价值排行等图层。
- `D3SandboxThreeMvp.tsx`：核心 3D 沙盘交互。
- `D4Visualization.tsx`：曲线监测视图。
- `D5WordCloud.tsx`：词云视图。

## 开发规则

1. D1 到 D5 保持单向数据流，不互相直接改内部状态。
2. D3 与 D4、D5 的联动契约集中定义，不分散硬编码。
3. 颜色、动画时长、布局阈值等视觉参数优先配置化。
4. 3D、图表、词云都要考虑大数据量下的重算、重绘和抖动。

## 常见错题

### 错题 1：联动契约散落

正确做法：节点选择、板块切换、图表和词云之间的输入输出契约集中维护。

### 错题 2：3D 沙盘持续重算

正确做法：把昂贵计算缓存或按需触发，避免每次 UI 状态变化都重建 Three.js 场景。

### 错题 3：视觉参数写死

正确做法：将颜色、时长、阈值放入配置常量，便于 D1 到 D5 一致调整。

## 扩展性审查

- 增加新节点或新板块是否无需重构全部映射。
- 大数据量下是否存在明显性能瓶颈。
- 3D 交互契约是否稳定可回归。
