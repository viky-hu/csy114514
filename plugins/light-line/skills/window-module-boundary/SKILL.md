# 窗口模块边界

## 总原则

每个窗口目录都是独立模块边界。跨窗口能力通过 `shared` 组件和明确 props 契约共享，禁止一个窗口直接修改另一个窗口的内部状态。

## 文件职责

- `*/<WindowName>Window.tsx`：窗口级编排、状态汇聚、子组件装配。
- `*/components/*.tsx`：局部视图与交互实现。
- `shared/*.tsx`：可复用 UI 或交互能力，不能耦合单窗口私有状态。

## 新功能落地

1. 先写清主责文件和协同文件。
2. 新增状态时声明状态唯一来源。
3. 影响多个窗口时评估是否抽到 `shared`。
4. 涉及模块职责变化时更新架构文档。

## 扩展性审查

- 再增加一个窗口是否能复用现有通路。
- 再增加一个后端模式是否需要大改。
- 是否存在重复代码可当次收敛。
- 是否出现状态双源或职责重叠。

## 判断是否进 shared

进 `shared` 的条件：两个以上窗口复用；能力本身不依赖单窗口私有状态；props 可稳定向后兼容。

不进 `shared` 的条件：只服务某个窗口；依赖该窗口状态机；抽出去会造成更多透传和耦合。
