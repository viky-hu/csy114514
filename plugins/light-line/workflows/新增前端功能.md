# 新增前端功能 Workflow

## 适用场景

当需要在 `apps/main-platform` 新增用户可见功能、入口、组件状态或交互流程时使用。

## 目标效果

新增功能要符合项目技术栈、窗口边界和交付门禁，不把业务聚合、共享状态或后端密钥误塞进 UI 组件。

## 应加载的 Skills

- `frontend-stack-mistake-book`
- `frontend-component-mistake-book`
- `frontend-ui-mistake-book`
- `repo-delivery-governance`
- `window-module-boundary`

## 执行步骤

1. 读取根 `AGENTS.md` 和目标目录更深层 `AGENTS.md`。
2. 判定功能归属窗口、主责文件和协同文件。
3. 检查是否已有共享组件、服务层或动画工具可复用。
4. 按现有 Next.js App Router、React、TypeScript、Tailwind、shadcn/ui 和 GSAP 约定实现。
5. 若职责边界变化，同步更新架构索引和扩展性审查记录。
6. 交付时说明功能归属、扩展性审查、必要重构和验证结果。

## 验收标准

- 没有跨窗口读取私有状态。
- 没有把后端密钥、节点地址或慢聚合暴露到前端组件。
- UI 文案、密度、层级和交互状态符合现有项目风格。
- 必要测试或类型检查已运行，未运行则说明原因。
