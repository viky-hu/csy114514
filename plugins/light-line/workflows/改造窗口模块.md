# 改造窗口模块 Workflow

## 适用场景

当改动 Window 1 登录、Window 2 宏观、Window 3 数据库或 Window 4 聊天窗口时使用。

## 目标效果

窗口内部可以演进，但窗口之间保持清晰边界；共享逻辑只上提到 `windows/shared` 或稳定服务层，不制造隐式耦合。

## 应加载的 Skills

- `window-module-boundary`
- `shared-component-governance`
- `window4-chat-governance`
- `database-window-governance`
- `macro-window-governance`
- `frontend-component-mistake-book`

## 执行步骤

1. 确认改动属于哪个窗口，并读取该窗口目录下的 `AGENTS.md`。
2. 区分展示组件、状态源、服务层、动画工具和共享组件。
3. 只在目标窗口内部改私有行为；跨窗口复用必须提炼成纯 helper 或稳定 shared 组件。
4. 对聊天窗口改造，特别检查 FLIP 捕获时机、portal 弹窗、会话 ID 同步和存储模式位置。
5. 对数据库窗口改造，区分列表、详情、预览和写回边界。
6. 对宏观窗口改造，保持 D1-D5 单向数据和中心化联动。

## 验收标准

- 主责窗口文件和协同文件可明确说明。
- shared 层没有混入窗口私有状态或业务分支。
- 组件职责没有从纯渲染膨胀成状态管理。
- 改造后的窗口入口、返回、加载、空态和错误态完整。
