# 优化动效时间轴 Workflow

## 适用场景

当改动登录首屏、产品三面板、聊天入场、菜单展开、SVG 时间轴、GSAP/Rive/Three.js/vis-network 动效时使用。

## 目标效果

动效保持清晰的时间轴、可退出状态和性能边界；首屏关键动画期间不并发初始化重负载模块。

## 应加载的 Skills

- `frontend-motion-mistake-book`
- `frontend-timeline-mistake-book`
- `frontend-ui-mistake-book`
- `trace-graph-physics-optimization`
- `repo-delivery-governance`

## 执行步骤

1. 先写清动画阶段：初始态、进入态、交互态、退出态、最终静止态。
2. GSAP 优先使用 `transform` 和 `opacity`，避免高频 `filter`、`blur`、大阴影、布局属性。
3. hover 和频繁交互只更新变更目标，不全量重建 timeline。
4. Three.js/WebGL 只作为背景或复杂视觉层，不能挡住主交互。
5. vis-network 或复杂图谱需要限制 physics 稳定时间、节点数量和交互重算范围。
6. 覆盖 Edge + 125% 缩放检查，记录结论和残余风险。

## 验收标准

- 动画没有遮挡关键文本和按钮。
- 首屏没有因为图谱、WebGL 或复杂物理布局导致卡顿。
- 时间轴状态可复现，退出和返回不会遗留样式。
- 降低动效或慢设备下仍可读、可操作。
