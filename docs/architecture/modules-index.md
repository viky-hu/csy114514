# Modules Index

## apps/main-platform

Main Next.js App Router frontend. It owns routing, app layout, first-party CSS, and same-origin BFF route handlers.

- `app/layout.tsx`: root HTML shell and global style imports.
- `app/page.tsx`: initial login entry screen and same-route switch into the main workspace after the local Agent loading flow completes.
- `app/api/**/route.ts`: BFF layer for frontend-to-server boundaries.
- `app/windows/login/LoginIntroWindow.tsx`: Window 1 login surface copied from `C:\Users\Admin\final-main\final-main`, including the viewport-pinned SVG root, mouse-following band, inverted text overlay, auth-state CTA copy, CTA animation, Escape close behavior, mock sign-in close flow, login-gated scroll band expansion with top-position pointer unlock and first-scroll preservation of the current band width, plus the fixed second-page Agent entry prompt, local draft overlay, and locked mock loading state after either Agent action. Its pointer-follow and leave-collapse interactions are gated to the top pointer mode so non-top scroll/second-page/loading states cannot collapse the full blue band.
- `app/windows/login/LoginForm.tsx`: Window 1 mock login/register form. During MVP it preserves the SVG-styled input surface while treating login and apply-register actions as unconstrained successful sign-in events.
- `app/windows/login/AgentConnectDraft.tsx`: Local-only second-page Agent connection draft. It collects API adapter fields and current `AgentManifest` fields, shows a security profile precheck, and keeps JSON details collapsed without adding a BFF route, posting to `/agents`, or changing the frozen backend contract.
- `app/windows/main/MainWindow.tsx`: Main workspace SVG shell entered after the Agent loading overlay fades out. It starts from a full-screen blue SVG cover, then uses a GSAP timeline to collapse it into a horizontal separator line and reveal real SVG white top/main surface rectangles for later workspace content. It also owns the SVG-aware left navigation placement, tightened sidebar width boundary, default dashboard selection, content-region replacement, page fade-out/fade-in swapping, and intro timing for the main workspace; the content region is intentionally close to the sidebar menu body while retaining larger right/bottom safety insets at 100% browser zoom.
- `app/windows/main/MainLineSidebar.tsx`: React port of the Vue Bits line-sidebar interaction pattern for the main workspace. It keeps pointer-proximity RAF smoothing, active-item state, semantic nav buttons, and project-owned CSS without adding Vue or shadcn-vue runtime dependencies.
- `app/windows/main/overview/**`: Default Dashboard/总览 content for the main workspace. It adapts `shared/fixtures` AgentProfile, AttackGraph, and EvaluationReport data into a local `OverviewViewModel`, including explicit R4 step metadata for `SOURCE -> AGENT -> MEMORY -> AGENT -> TOOL`. `OverviewDashboard` owns page composition and the wide-graph/narrow-side-stack balance, while `OverviewR4Graph`, `overview-r4-layout.ts`, and `overview-r4-svg-viewport.ts` own the private `1000x440` graph coordinate space, the dedicated left layer-info lane with independent foreground SVG text and no label container, three taller horizontal semantic lanes, fixed icon/title/caption node content slots, node-bounds-derived x-axis hover hot zones whose frosted-column left/right edges exactly match each node rectangle's measured horizontal bounds after the SVG's rendered `xMidYMid meet` viewport offset/scale is applied, GSAP-driven frosted-column opacity and rail emphasis without a moving sheen block, arrowless orthogonal SVG route anchors aligned to node rectangle edge centers, scoped GSAP timelines, DrawSVG-style hover outlines, and reduced-motion direct-set behavior. HTML hover strips, popover hitboxes, and pointer hit testing must use the rendered SVG matrix/content viewport rather than frame-wide percentages so large monitors, laptop screens, and narrow containers stay aligned without `preserveAspectRatio="none"`. The graph remains a dashboard overview component rather than the full Anatomy attack-graph page, and the fixture-shaped adapter remains the only data boundary so a later BFF-backed repository can replace the source without changing the visual layer.
- `app/windows/main/anatomy/**`: Attack Graph/攻击图谱 content for the main workspace. It is the full risk-path workbench described by section 4.3, separate from both the dashboard R4 thumbnail and the Security Profile boundary confirmation page. `anatomy-data.ts` owns the normalized preview/live view model, status split, selected-path defaults, R4 TestCase/AttackSeed verification metadata, and the rule that `risk_path_ids` only means 待验证 while `evaluationReport.findings` is the only 已验证 source. `anatomy-repository.ts` owns the internal `MockAnatomyRepository` / `ApiAnatomyRepository` boundary: the page first renders fixture preview data, then tries same-origin `GET /api/agents/{agentId}/graph`, converts valid payloads into live view models with no report-backed verification, and falls back to the mock repository on 404/503/invalid payloads without calling `POST /agents` or the FastAPI backend directly. `AnatomyGraph` owns the SVG + GSAP workbench, compact data-source marker, path cards aligned below the map frame, right-side path inspector plus selected-node detail inspector, safety-label chips, evaluation handoff, and empty state; the visible preview/live switch panel is intentionally omitted in the current frontend build so graph space stays dominant while still exposing fixture/API source state. `anatomy-graph-layout.ts` owns the private `1000x520` five-stage attack-chain coordinate space (`入口 -> 初次解析 -> 持久化 -> 二次唤起 -> 外发动作`), deterministic curved R1/R2/R3/R4 route geometry, one visible curve per source/target node pair, uniform `150x88` node rectangles, edge-center node anchors, selected-route endpoint node derivation, bottom phase-rail placement, and human-readable visual node aliases such as 恶意网页, Agent 解析, 长期记忆, 二次唤起, and 发送邮件. Shared edges list every matching risk path in `pathIds`; for example `Agent 解析 -> 发送邮件` is a single curve shared by R1 and R3 rather than two overlapping route drawings. Active node emphasis is the union of explicit path steps and every selected route's source/target endpoints, so nodes such as `读取邮件` stay highlighted whenever a selected R path visibly connects through them. The visual coordinate system applies a shared `+48x/+28y` offset to nodes, routes, control points, phase labels, and hitboxes so the graph's content mass sits closer to the map-frame center instead of drifting to the upper-left. The Anatomy graph uses the outer map panel as its only visible frame and stage boundary; the two-row R1/R2/R3/R4 path-card grid stretches through the remaining left-column height while keeping a small bottom safety inset so the lower card borders stay visible, and the path cards plus right inspector keep a slightly larger reading scale than the initial preview build. It must not reintroduce a second inner SVG rectangle, detached internal width cap, duplicate visible edges for the same node pair, non-uniform Anatomy node rectangles, `preserveAspectRatio="none"`, or scaling-based active node highlight.
- `app/windows/main/evaluation/**`: Real Evaluation Run/Report vertical slice. `EvaluationWorkspaceProvider` owns validated sessionStorage recovery, the evaluation snapshot, event cursor, SSE lifecycle, and event reducer above the keyed content shell; run and report views consume the same state and generated OpenAPI response shapes. The run view mirrors the three persisted stages, real event-driven step illumination, scoped GSAP state transitions, and a redacted read-only terminal; the report view reads the persisted report and trace and exposes score breakdown, causal findings, five-node evidence path, and remediation without rebuilding the full attack graph.
- `app/api/evaluations/**` and `app/lib/contracts/backend-api.d.ts`: Same-origin Node BFF for evaluation creation, start, snapshot, event stream, trace, and report. `backend-openapi.json` is the FastAPI generation input; `backend-api.d.ts` is generated with `openapi-typescript` and must be regenerated after the public API changes. SSE proxying preserves `Last-Event-ID`, request cancellation, no-cache/no-transform, and anti-buffering headers; backend URLs remain server-only.
- `app/lib/server/backend.ts` and `app/api/agents/[agentId]/graph/route.ts` / `app/api/evaluations/[evaluationId]/report/route.ts`: Same-origin BFF boundary for live attack-graph and evaluation-report connections. Graph proxy failures return the shared `{ error: { code, message, details } }` shape so frontend repositories can fall back cleanly. The frontend does not call the FastAPI backend directly or expose backend secrets through `NEXT_PUBLIC_*`.
- `app/windows/shared/evaluation-handoff.ts`: Frontend handoff store for carrying `agentId`, `riskPatternId`, and `testCaseId` from the attack graph into the evaluation/run page without changing backend contracts.
- `app/windows/main/shared/graph-svg-primitives.ts`: Main-window SVG graph primitives shared by overview and profile graph modules. It owns centered-rectangle bounds and clockwise rounded-rectangle path generation so feature graphs reuse the same SVG node geometry instead of maintaining near-duplicate helpers.
- `app/windows/main/profile/**`: Security Profile/安全画像 content for the main workspace. It adapts the same fixture-shaped AgentProfile and AttackGraph data into a local `SecurityProfileViewModel`, keeping the boundary confirmation page separate from the later attack-analysis page. `SecurityProfileGraph` owns the Agent-centered boundary map, selected-node inspector, overview-style HTML hot zones, HTML node hitboxes, foreground SVG column text, DrawSVG hover outlines, and scoped GSAP reveal/highlight behavior, including the page-level reveal choreography that brings the header, map, inspector, and footer in after mount; `security-profile-graph-layout.ts` owns the private `1000x500` SVG coordinate space, explicit inner graph boundary, fixed node bounds, ViewBox-derived hover bands, edge-center node anchors, deterministic curved route segments, and coordinate hit testing while using shared main-window SVG primitives for node geometry. The profile graph uses overview-isomorphic transparent rectangular nodes (`path surface + DrawSVG outline + lucide icon + centered label/caption`) and four equal-gap column bands (`90-242`, `310-484`, `552-712`, `780-944`) whose SVG bands, HTML hover strips, hitboxes, and route anchors are derived from the same ViewBox data. Unlike the overview's single attack-chain path, profile routes now share one blue-purple gradient stroke for all curves and hover outlines while preserving routeTone metadata only as semantic labeling, so default relationships stay quiet without splitting the palette. The profile graph must not use pixel-positioned hover strips, circular marker/initial nodes, horizontal hover translation, full-width layout animation, or `preserveAspectRatio="none"`; node hover keeps x coordinates stable with a shared y/scaleY/outline treatment. The graph keeps only the five main semantic routes (`browser -> agent`, `email data -> email.read`, `agent -> email.read`, `agent -> email.send`, `agent -> memory`) and does not add the fixture's `memory -> agent` back edge to avoid loop-like visual clutter. The module does not invent fixture-missing delete/DENY tools, add BFF routes, or introduce another animation/style dependency.
- `app/windows/**`: feature-owned window modules aligned with the final repository shape.
- `app/styles/**`: app-level and feature-level CSS.
